# Contributing

Thanks for helping. This guide covers every Bates Solutions repository. A repository with its own
`CONTRIBUTING.md` uses that one instead.

## Before you start

- **Small fixes:** open a pull request.
- **Bigger changes:** open an issue first, so we can agree on the approach before you spend time on
  it.
- **Security problems:** don't open an issue. Follow [SECURITY.md](https://github.com/Bates-Solutions/.github/blob/main/SECURITY.md).

## Making a change

1. Fork the repository and create a branch from `main`.
2. Make the change, with tests where the repository has them.
3. Run the checks listed in the README's **Development** section. CI runs the same checks on every
   pull request.
4. Update the README or docs if the change affects how someone uses the project.

## Commits

Write commit messages that say what changed and why. Repositories that release automatically use
[Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:` and so on),
and their README says so.

## Pull requests

- Keep each pull request to one change.
- Fill in the pull request template.
- Never include an API key, token or personal data in code, tests, fixtures or screenshots.

By contributing, you agree that your contribution is licensed under the repository's license, and
you agree to follow the [code of conduct](https://github.com/Bates-Solutions/.github/blob/main/CODE_OF_CONDUCT.md).
